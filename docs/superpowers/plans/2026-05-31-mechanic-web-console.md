# Mechanic Web Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the local open-mechanic web app so one terminal command can run it with or without a browser GUI, while the web UI clearly distinguishes offline, disconnected, and connected adapter states and serves a mechanic/engineer diagnostic workflow.

**Architecture:** Keep the existing Python CLI, FastAPI `DashboardService`, and React/Vite frontend. Add explicit adapter state to the API, add best-effort browser launching controlled by `--no-gui`, and replace the rail-based React dashboard with a single diagnostic console composed from focused workflow sections.

**Tech Stack:** Python 3.11, argparse, FastAPI, uvicorn, Pydantic v2, pytest, React 19, TypeScript, Vite, CSS.

---

- Replace `frontend/src/styles.css`: responsive utility dashboard styling without side rail.

```python
def _open_web_gui(url: str, console: Console) -> None:
    import webbrowser

    try:
        opened = webbrowser.open(url, new=2)
    except Exception as exc:  # pragma: no cover - depends on local desktop
        console.print(f"[yellow]Could not open browser:[/yellow] {exc}")
        return
    if not opened:
        console.print("[yellow]Could not open browser automatically.[/yellow]")
```
